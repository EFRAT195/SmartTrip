# SmartTrip – סוכן AI לתכנון טיולים חכם

**SmartTrip** הוא יישום לתכנון טיולים בישראל באמצעות סוכן בינה מלאכותית (AI Agent), הבונה מסלול אישי בהתאם להעדפות המשתמש, למגבלות הזמן והתקציב ולמועד הטיול.

המערכת משלבת מודל שפה, הפעלת כלים (Tool Calling), בדיקות תקינות, נתוני מזג אוויר משירות חיצוני וממשק משתמש אינטראקטיבי.

**הייחוד של SmartTrip:** הסוכן אינו מסתפק ביצירת המלצה. הוא בוחר אטרקציות, בודק את החלטותיו, משנה אותן בעת הצורך, ומשתמש במידע שהתקבל כדי להתאים גם את הציוד המומלץ לטיול.

---

## הבעיה שהפרויקט פותר

תכנון טיול דורש בדרך כלל חיפוש אטרקציות, השוואת אפשרויות, חישוב זמני ביקור ועלויות והתחשבות במזג האוויר.

לעיתים מסלול שנראה מתאים בתחילה מתברר כארוך מדי או יקר מדי, ויש צורך לתכנן אותו מחדש.

SmartTrip מרכז את התהליך במערכת אחת ומאפשר למשתמש לקבל מסלול מותאם אישית, תוך בדיקת התאמתו למגבלות שהוגדרו.

צילומי המסך של המערכת זמינים בתיקיית [screenshots](./screenshots).

ההדגמה כוללת את ממשק הזנת הנתונים, המסלול שנבחר, תחזית מזג האוויר, המלצות הציוד ויומן הפעולות של הסוכן.

בעקבות תוצאת הבדיקה, הסוכן שינה את בחירת האטרקציות וביצע בדיקה חוזרת. המסלול המתוקן אושר עם משך ביקור של שעה וחצי ועלות של 0 ₪.

לאחר מכן הסוכן בדק את תחזית מזג האוויר והפיק שתי המלצות ציוד מותאמות.

הדוגמה ממחישה תהליך של **בחירה → בדיקה → זיהוי חריגה → תיקון → אימות חוזר → התאמת המלצות**.

## כיצד המערכת פועלת?

### 1. קבלת העדפות המשתמש

המשתמש מזין חמישה פרטים:

- אזור הטיול
- סוג הטיול הרצוי
- מספר השעות הפנויות
- תקציב מקסימלי
- תאריך הטיול

### 2. חיפוש אטרקציות

הסוכן מפעיל את הכלי `search_attractions`, שמחזיר אטרקציות מתאימות מתוך מאגר JSON מקומי, בהתאם לאזור ולקטגוריה שנבחרו.

### 3. בחירת מסלול

מודל ה־AI בוחר מתוך האטרקציות שנמצאו את האטרקציות שירכיבו את המסלול.

הבחירה מתבצעת בהתאם להעדפות המשתמש ולמגבלות שהוגדרו, ולא באמצעות מסלול קבוע מראש.

### 4. בדיקת מגבלות

הסוכן מפעיל את הכלי `check_trip`, שבודק את המסלול שנבחר מבחינת משך הביקור הכולל והעלות הכוללת.

הכלי מחזיר לסוכן תוצאה מובנית, הכוללת מידע על תקינות המסלול ועל חריגות אפשריות.

### 5. זיהוי חריגה ותיקון עצמאי

כאשר הבדיקה נכשלת, הסוכן מקבל את תוצאת הבדיקה ומחליט כיצד לשנות את בחירת האטרקציות.

לאחר השינוי הוא יכול להפעיל מחדש את כלי הבדיקה, עד לקבלת מסלול תקין במסגרת תהליך העבודה שהוגדר.

המערכת אינה מציגה מסלול שנכשל בבדיקת המגבלות כמסלול מאושר.

### 6. בדיקת מזג האוויר

לאחר אישור המסלול, הסוכן מפעיל את הכלי `get_weather`, שמקבל נתוני תחזית באמצעות שירות Open-Meteo.

נתוני מזג האוויר משמשים להמשך התאמת ההמלצות למשתמש, כאשר תחזית זמינה לתאריך ולאזור המבוקשים.

### 7. קבלת החלטות על ציוד אישי לטיול

זהו שלב נוסף שבו הסוכן מקבל החלטות על בסיס מידע שנאסף במהלך העבודה.

לאחר קבלת פרטי המסלול ונתוני מזג האוויר, מודל ה־AI מחליט אילו פריטי ציוד כדאי למשתמש לקחת.

**רשימת הציוד אינה קבועה מראש.** היא נוצרת באופן דינמי בהתאם למאפייני הטיול ולתחזית, ולכל פריט מצורף הסבר לבחירתו.

לדוגמה:

- כאשר צפוי גשם, הסוכן עשוי להמליץ על מטרייה או מעיל גשם.
- כאשר המסלול כולל הליכה בטבע, הסוכן עשוי להמליץ על נעלי הליכה נוחות.
- בתנאי מזג אוויר שונים, הסוכן עשוי להתאים את המלצותיו בהתאם.

כך הסוכן משלב מידע מהמסלול וממקור חיצוני לצורך קבלת החלטה נוספת.

### 8. הצגת התוצאה והסבר ההחלטות

המשתמש מקבל:

- מסלול טיול עם האטרקציות שנבחרו
- משך הביקור והעלות הכוללת
- הסבר לבחירת המסלול
- נתוני מזג האוויר
- המלצות ציוד אישיות והסבר לכל פריט
- יומן פעולות המתאר את תהליך העבודה של הסוכן

## מדוע מדובר בסוכן AI ולא בצ'אט רגיל?

בצ'אט רגיל המשתמש שולח בקשה ומקבל תשובה שנוצרת על ידי מודל השפה.

ב־SmartTrip המודל פועל כחלק מתהליך רב־שלבי שבו הוא **מחליט אילו כלים להפעיל, משתמש בתוצאותיהם ומקבל החלטות לגבי המשך העבודה**.

המערכת משתמשת במנגנון Function / Tool Calling של OpenAI.

הסוכן מבצע שלושה סוגים מרכזיים של החלטות:

**בחירת אטרקציות:** בחירת הרכב מסלול מתוך האפשרויות שנמצאו, בהתאם לדרישות המשתמש.

**תיקון מסלול:** כאשר כלי הבדיקה מזהה חריגה, הסוכן יכול לשנות את הבחירה ולבצע בדיקה חוזרת, במקום להחזיר מסלול שאינו תקין.

**התאמת ציוד אישי:** לאחר קבלת נתוני המסלול ומזג האוויר, הסוכן מחליט אילו פריטים מומלצים ומנמק כל המלצה.

הכלים אחראים לביצוע פעולות ולבדיקות מוגדרות, ואילו המודל אחראי לבחירת הפעולות, לפרשנות התוצאות ולהחלטות שמתקבלות במהלך התהליך.

## הכלים של הסוכן

| כלי | תפקיד |
|---|---|
| `search_attractions` | חיפוש אטרקציות לפי אזור וקטגוריה במאגר המקומי |
| `check_trip` | בדיקת משך הביקור והעלות מול מגבלות המשתמש |
| `get_weather` | קבלת נתוני תחזית מזג אוויר משירות Open-Meteo |

בנוסף, מודל השפה משמש לבחירת המסלול, לתיקון החלטות, לניסוח הסברים וליצירת המלצות ציוד מותאמות.

## ארכיטקטורת המערכת

המערכת מחולקת לשני חלקים מרכזיים:

**Backend – Python + FastAPI**

שרת ה־API מקבל את נתוני המשתמש, מפעיל את הסוכן ומחזיר תוצאה מובנית לממשק.

קובץ `agent.py` מרכז את לוגיקת הסוכן ואת תהליך הפעלת הכלים. הכלים עצמם ממומשים בקבצים נפרדים, כדי להפריד בין קבלת החלטות לבין ביצוע פעולות.

**Frontend – React + TypeScript + SCSS**

ממשק המשתמש מאפשר להזין את פרטי הטיול, לשלוח בקשה לשרת ולהציג את תוצאות התכנון בצורה חזותית.

בנוסף לתוצאה הסופית, הממשק מציג את שלבי העבודה של הסוכן, כולל בדיקות, חריגות ותיקונים.

## הוראות התקנה והרצה

### דרישות מקדימות

יש לוודא שמותקנים במחשב:

- Python
- Node.js ו־npm
- מפתח API תקף של OpenAI
- חיבור לאינטרנט לצורך הפעלת שירותי ה־API

### שלב 1 – הורדת הפרויקט

```bash
git clone https://github.com/EFRAT195/SmartTrip.git
cd SmartTrip
```

### שלב 2 – יצירת סביבה וירטואלית והתקנת תלויות

ב־Windows PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

### שלב 3 – הגדרת מפתח OpenAI

יש ליצור קובץ בשם `.env` בתיקייה הראשית של הפרויקט, ולהוסיף בו:

```env
OPENAI_API_KEY=your_api_key_here
```

יש להחליף את `your_api_key_here` במפתח API תקף.

**מטעמי אבטחה, קובץ `.env` אינו מועלה ל־GitHub.**

### שלב 4 – הפעלת שרת ה־Backend

מתוך התיקייה הראשית של הפרויקט:

```powershell
.\.venv\Scripts\python.exe -m uvicorn main:app --reload --port 64161
```

השרת יפעל בכתובת:

`http://127.0.0.1:64161`

ניתן לפתוח את תיעוד ה־API האינטראקטיבי בכתובת:

`http://127.0.0.1:64161/docs`

### שלב 5 – הפעלת ממשק המשתמש

יש לפתוח טרמינל נוסף, מתוך התיקייה הראשית של הפרויקט, ולהריץ:

```powershell
cd frontend
npm install
npm run dev
```

לאחר מכן יש לפתוח בדפדפן את הכתובת שמציג Vite, בדרך כלל:

`http://localhost:5173`

יש להשאיר את שרת ה־Backend ואת שרת ה־Frontend פעילים במקביל.

### שלב 6 – הפעלת הסוכן

בממשק המשתמש:

1. בוחרים אזור וקטגוריית טיול.
2. מגדירים זמן פנוי ותקציב מקסימלי.
3. בוחרים תאריך.
4. שולחים את הבקשה לתכנון מסלול.
5. צופים במסלול, בתחזית, בהמלצות הציוד וביומן הפעולות.

## שקיפות תהליך קבלת ההחלטות

אחד המאפיינים המרכזיים של SmartTrip הוא יומן הפעולות המוצג למשתמש תחת הכותרת **״מאחורי הקלעים״**.

היומן מאפשר לראות אילו פעולות הסוכן ביצע ומה היו תוצאותיהן.

כאשר מתגלה חריגה במסלול והסוכן מבצע ניסיון תיקון, היומן מציג את החריגה, את שינוי הבחירה ואת תוצאת הבדיקה החוזרת.

כך אפשר להתרשם לא רק מהמסלול הסופי, אלא גם מתהליך קבלת ההחלטות שהוביל אליו.

## מגבלות והערות

- מאגר האטרקציות הוא מאגר JSON מקומי שנבנה לצורך הדגמת הפרויקט, ולא חיפוש בזמן אמת באינטרנט.
- זמני הביקור והעלויות מבוססים על נתוני המאגר והם לצורך הערכה והדגמה.
- בדיקת מגבלות הזמן מתייחסת למשכי הביקור הרשומים במאגר; היא אינה מהווה חישוב ניווט או זמני נסיעה בין האטרקציות.
- תחזית מזג האוויר מתקבלת משירות חיצוני, בהתאם לזמינות הנתונים.
- המלצות הציוד נוצרות באופן דינמי על ידי מודל השפה ועשויות להשתנות בין ריצות.
- מאחר שהמודל מקבל החלטות דינמיות, לא בכל הרצה תתרחש חריגה או יתבצע תיקון מסלול.
- הפעלת הסוכן מחייבת מפתח OpenAI תקף ועשויה להיות כרוכה בעלויות API.
